# Apps

Manage **integration apps** in the active workspace (Postman-style API definitions, actions, environments).

Requires: `ductape login` and an active workspace.

## Commands

```bash
ductape apps list
ductape apps list --status active
ductape apps get --id <app_id>
ductape apps get --tag <app_tag>
ductape apps create              # interactive prompts
ductape apps create -f app.json
ductape apps update --id <app_id> -f patch.json
ductape apps update --tag <app_tag> --proxy -f patch.json
ductape apps delete --id <app_id>

# Import Postman v2.1 or OpenAPI 3.0
ductape apps import ./stripe.json --type postman
ductape apps import ./api.yaml --type openapi
ductape apps import ./collection.json --type postman --app-tag my-workspace:stripe --update
```

## Webhook Definitions

Manage webhook groups and event definitions without registering provider endpoints
or publishing the app. These commands use the SDK proxy's top-level `webhooks`
module, not `app.webhooks`.

```bash
ductape apps webhooks list --app stripe:payments --json
ductape apps webhooks get --app stripe:payments --webhook payments --json
ductape apps webhooks create --app stripe:payments --definition-file ductape/webhooks/payments.json
ductape apps webhooks update --app stripe:payments --webhook payments --definition-file ductape/webhooks/patch.json
ductape apps webhooks delete --app stripe:payments --webhook payments
ductape apps webhooks events list --app stripe:payments --webhook payments --json
ductape apps webhooks events create --app stripe:payments --webhook payments --definition-file ductape/webhooks/paid.json
ductape apps webhooks events get --app stripe:payments --webhook payments --event paid --json
ductape apps webhooks events update --app stripe:payments --webhook payments --event paid --definition-file ductape/webhooks/paid-patch.json
ductape apps webhooks events delete --app stripe:payments --webhook payments --event paid
```

Use a local event `tag` such as `paid` in the JSON file. The CLI qualifies it with
the parent webhook tag. Inspect the live schema before preparing definitions:
webhook groups require `name`, `tag`, `description`, and `envs`; events require
`name`, `tag`, `description`, `selector`, and a provider-backed `sample`.
Verify provider signature handling and registration separately before publishing.
All operations support `--profile` and `--json`. Creation and updates require
`--definition-file` to avoid collision with the parent command's `--file` option.

## Import (Postman / OpenAPI)

Imports use `POST /apps/v1/import` (same as the Workbench). Supported formats:

| `--type` | Format |
|----------|--------|
| `postman` | Postman Collection **v2.1** (JSON) |
| `openapi` | **OpenAPI 3.0** (JSON or YAML) |

```bash
# New app from collection (name taken from collection info / openapi title)
ductape apps import ./postman-collection.json --type postman

# OpenAPI spec
ductape apps import ./openapi.yaml --type openapi

# Update existing app (by tag or id)
ductape apps import ./v2.json --type postman --app-tag acme:stripe --update
ductape apps import ./v2.json --type postman --app-id 507f1f77bcf86cd799439011 --update
```

Options:

- `--update` — merge into an existing app when the tag already exists
- `--version` — required explicit version label; no automatic default. Verify the provider API version (including date-based versions) against the imported endpoints and version headers. For unversioned or mixed-version APIs, use an explicitly chosen integration revision instead of claiming a provider version. Add this flag to each import example above.
- `--json` — print API response

## How it works

| Verb | API |
|------|-----|
| `list` | `GET /apps/v1/workspace/:workspace_id/:status` |
| `get` | `GET /apps/v1/:id` or `GET /apps/v1/fetch/tag` |
| `create` | `POST /apps/v1/create` |
| `update` | `PUT /apps/v1/:id` or sdk-proxy `app.update` with `--proxy` |
| `delete` | `DELETE /apps/v1/:id` |

## Example: create app

`app.json`:

```json
{
  "app_name": "Stripe",
  "description": "Stripe API integration",
  "tag": "stripe",
  "base_url": "https://api.stripe.com"
}
```

```bash
ductape apps create -f app.json
```

Defaults added by the CLI: `workspace_id`, `user_id`, `public_key`, `version`, `logo`, `envs`.

## Connecting apps to products

After creating an app and product:

1. List apps on a product: `ductape products apps list --product <product_id>`
2. Connect via Workbench or sdk-proxy `product.apps.connect` (see [Products](./products))

## vs `resources app`

Use `ductape apps` for workspace app CRUD. Use `ductape resources app …` only for sdk-proxy operations when a project is linked.

`ductape apps list` is the correct way to list apps.
