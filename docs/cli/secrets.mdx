# Secrets

```bash
ductape secrets list
ductape secrets create -f '{"key":"API_KEY","value":"..."}'
ductape secrets get --key API_KEY
ductape secrets update --key API_KEY -f patch.json
ductape secrets delete --key API_KEY
```

Workspace-scoped via sdk-proxy `secrets` module.

## Save the secrets in a `.env` file

Instead of creating each secret by hand, scan a project's `.env` file and save the secrets in it to the workspace:

```bash
ductape secrets-scan-env                      # preview: reads ./.env, saves nothing
ductape secrets-scan-env --apply              # save what the preview showed
ductape secrets-scan-env --env-file .env.production --env prd --apply
```

The file is read on your machine and the values go from there to the workspace. They are never printed, never in the output, and never pass through an assistant. The output lists each variable's name, what was decided, why, and the value's length (so a truncated paste is noticed).

**What is saved.** By default a variable is saved when its name or its value says it is a credential: names such as `PASSWORD`, `TOKEN`, `SECRET`, `API_KEY`, `PRIVATE_KEY`, `DSN`, `CONNECTION_STRING`; values that look like a private key, a payment provider secret key (`sk_live_...`), an AWS access key id, a GitHub or Slack token, a signed token, or a URL with a password in it; and long random-looking strings. Variables that are sent to browsers by design (`NEXT_PUBLIC_*`, `VITE_*`, `REACT_APP_*`, `PUBLIC_*`) are configuration, whatever else the name says. Ports, hosts, regions, log levels, flags and numbers are configuration and are left alone.

**What is never saved.** An empty value, a placeholder (`changeme`, `your-key-here`, `<token>`), or a value that refers to another variable (`${OTHER}`), because the text on its own is not the value.

| Option | Effect |
|--------|--------|
| `--apply` | Save. Without it nothing is saved. |
| `--env <slug>` | Limit the saved secrets to one environment (`stg`, `prd`). Without it they are available in every environment. |
| `--only A,B` | Save exactly these variables, whatever they look like. |
| `--exclude A,B` | Never save these. |
| `--all` | Save every variable that has a real value, configuration included. |
| `--prefix APP_` | Put this in front of each name to make the secret's key. |
| `--overwrite` | Replace a secret the workspace already has. By default an existing secret is left alone. |
| `--env-file`, `--dir` | The file to read, and the project folder. Default: `.env` in the current folder. |

A preview works without logging in; saving needs a workspace login. A secret saved this way is used like any other: as `$Secret{NAME}` in your resources, or as `{ "secret": "NAME" }` in a [release's configuration](../deploy/build-and-release#configuration-holds-references-not-secrets). The output ends with the references to use.
